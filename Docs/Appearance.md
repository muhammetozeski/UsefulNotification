# HTML, themes, and frames

The native Windows caption, borders, resizing frame, and nonclient decoration are removed. The visible notification frame is HTML. The resident renderer uses C# theme objects to generate CSS; the shipped styles do not define CSS custom properties.

The default toast width is 392 physical pixels. Content determines height. Physical sizing compensates for display scaling so the compact card does not become larger on a 125% display. Change `AppConstants.Windows` to change the application's geometry policy.

## Named themes

Dark, Light, Blue, Emerald, Purple, Amber, Crimson, HighContrast, Info, Warn, Error, and Happy are provided. The semantic themes also supply a level when the request omits one. Theme selection is case-insensitive.

Place a `NotificationTheme` JSON document in `UserData\Themes`, relative to the portable program root. Use the Reload button after editing it. The theme contains `palette`, `typography`, `layout`, and `frame` objects. Their definitions and defaults are in [Themes.cs](../src/UsefulNotification.Core/Themes.cs).

```json
{
  "name": "Workshop",
  "frame": {
    "thickness": { "top": 2, "right": 2, "bottom": 2, "left": 6 },
    "cornerRadius": 0,
    "pattern": "solid",
    "accentEdges": "all",
    "accentColor": "#70a5cf"
  }
}
```

Select it with `notify.exe --theme Workshop`. Missing theme properties use their model defaults.

## A sender controls its own frame

```csharp
await NotificationClient.SendAsync(new()
{
    Title = "Build failed",
    Message = "Open the build log for details.",
    Theme = "Error",
    Appearance = new()
    {
        Frame = new()
        {
            Pattern = BorderPattern.Dashed,
            CornerRadius = 0,
            AccentEdges = BorderEdges.All,
            AccentColor = "#c95d64",
            Thickness = new() { Top = 2, Right = 2, Bottom = 2, Left = 5 }
        }
    }
});
```

The same `appearance` object can be sent as JSON. It can override the frame, palette, typography, and layout independently of the named theme. The ordinary card receives scoped CSS generated by the same C# stylesheet function, so a sender's theme does not change adjacent cards.

## Replace the entire card with HTML

On first launch, the program writes its editable default `Card.html` into `UserData\Templates`. Existing user files are preserved. A Custom request without a file name uses this template.

```powershell
.\notify.exe "Deployment complete" "The service is available." --type Custom
.\notify.exe "Report ready" "The report is available." --template "C:\MyProgram\Notifications\report.html"
```

Custom HTML replaces the complete card, rather than being placed inside a fixed notification frame. It runs in a sandboxed iframe and can define its own structure, typography, border, and controls. Its height is reported to the resident surface automatically.

Available substitutions are `{{title}}`, `{{message}}`, `{{source}}`, `{{time}}`, `{{id}}`, and `{{data.key}}` for request data. These values are HTML-escaped. `{{themeCss}}` contains generated CSS; `{{frameCss}}` contains the effective C# frame style. `{{dismissLabel}}` and `{{dismissAction}}` provide the localized default dismissal control.

To acknowledge the card:

```html
<button onclick="parent.postMessage({action:'{{dismissAction}}'}, '*')">{{dismissLabel}}</button>
```

To invoke a sender-declared action and return a reply:

```html
<input id="answer">
<button onclick="parent.postMessage({action:'confirm',reply:document.getElementById('answer').value}, '*')">Confirm</button>
```

Declare an action with id `confirm` in the request. The bridge accepts messages only from the matching notification frame, and accepts only the reserved dismissal or a declared action id. Command execution and URL opening are expressed by the request's action objects.

Template source and local images are cached with modification-time invalidation. Theme CSS is cached in memory. The broker keeps its native windows and Blazor surfaces alive after notifications close; new requests do not start a new renderer.
