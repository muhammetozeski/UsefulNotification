# Maintaining documentation

Document the public contract and the project-specific knowledge needed to use, modify, or package this application. Keep each fact in one place and link to it from the index. Update the relevant guide when the behavior changes.

Describe actual inputs, outputs, ownership, and recovery behavior. Separate source inspection, official documentation, runtime checks, and human visual confirmation. Do not describe an untested method as verified. Record the relevant conditions and limits when they change the conclusion.

Do not copy generic tutorials, raw logs, task plans, or temporary status into these guides. A dated Walkthrough record carries work context; these guides carry reusable instructions. Add a guide only when there is information worth preserving. Before finishing, check its local links and that a reader can perform the documented task without rediscovering missing steps.
