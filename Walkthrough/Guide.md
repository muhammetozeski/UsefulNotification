# Project handover

Choose records by their dated file names. Read the newest current context, the newest relevant accumulation record if one exists, and only the intervening experiences needed for the current task. Stop once the relevant context is understood; do not reread unchanged material.

When a result affects later work, add a new file named `yyyy.MM.dd HH.mm.ss - Meaningful subject.md` using the actual local creation time. State the current project context, the observation that changed the approach, the result, and what the next worker should do differently. Use a few concise paragraphs, with links to detailed guides rather than duplicate instructions.

Do not turn Git changes or tool output into a work diary. Preserve failed assumptions when they prevent repeated mistakes. Distinguish inspection from runtime verification and human confirmation. Never invent past work. If several records become necessary just to understand the project, create a new dated accumulation record preserving the useful lessons. Correct an invalidated conclusion explicitly in a new record; do not silently rewrite its history.

The goal of minimizing reading applies to this handover process. It does not reduce the scope or quality of implementation work.
