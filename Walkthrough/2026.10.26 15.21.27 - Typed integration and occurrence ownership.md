The resident Windows renderer remains MAUI Blazor, with the 392-physical-pixel HTML frame and tray panel. The initial version exposed string selectors despite the requested object ownership. Follow [Development](../Docs/Development.md) for the request-to-result flow.

Independent source review found six concrete gaps during implementation: calendar calculations compared dates in different offsets; recovery discarded accepted reply fields; visible lifetime edits retained the old expiry; Retry reused the editing path; JSON discriminators depended on property order; and standard Razor handlers read the latest entry instead of the render that produced the control. These were corrected before delivery. Normalize calendar calculations to the anchor offset, preserve PendingResult when recording an interrupted outcome, resolve lifetime policy in one place, keep Retry distinct from Replace, allow out-of-order metadata, and capture the render's immutable occurrence/revision in event closures. Backend stale-message tests alone do not inspect which identity a UI handler sends.
