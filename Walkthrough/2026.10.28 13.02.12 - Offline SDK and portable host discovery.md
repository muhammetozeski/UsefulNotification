# Offline SDK and portable host discovery

UsefulNotification 2.1.0 now delivers the real Core NuGet package and its exact Polly.Core dependency in a separate offline SDK. The installer registers its adjacent Packages folder once at account scope and lets ordinary NuGet restore populate the configured global cache. It checks the bundled archive hashes and required cache files before deciding whether to restore. Isolated checks covered an empty cache, a complete-cache fast path, a missing DLL, a moved source, and preservation of another source and a newer sentinel version. The actual account installation then restored Core and skipped restore on the next invocation. Keep package archives in the durable SDK folder; they provide recovery after explicit cache cleanup. See [Integration](../Docs/Integration.md) and [the SDK instructions](../Sdk/README.md).

The first normal host launch records its current launcher under the Windows account; new callers use only PackageReference and SendAsync. A real package consumer built without a project/DLL reference, connected to the relocated Windows release without an Application override, and automatically restarted that stopped release using registration. Launch once after moving the host to refresh discovery. Explicit Application remains available for deliberate overrides.

For same-account elevated senders, own the pipe with WindowsIdentity.User and use explicit account access rather than the token's Owner group. The client verifies the server owner and requests identification instead of impersonation. An attempted explicit integrity label through PipeSecurity's audit section made ordinary named-pipe creation fail with privilege-not-held. Removing that unnecessary audit change retained the normal host's native medium integrity. Actual normal and elevated client processes both received accepted receipts from that normal host. This verification concerns elevated senders, not a requirement to elevate the desktop host.

Publishing now requires a disposable external output directory. User instructions changed the previous source/publish convention: build copies and release archives stay under NewTemp, while only the application and durable SDK are installed permanently. Independent review found the source-root equality case, repeat SDK publication into a nonempty folder, and an obsolete mandatory executable-path example; these were corrected. The current [build guide](../Docs/Build.md) owns the maintained procedure. Disposable evidence is under C:\C\UsefulNotificationSdk, C:\C\UsefulNotificationSdka, and C:\C\UsefulNotificationPublish.
