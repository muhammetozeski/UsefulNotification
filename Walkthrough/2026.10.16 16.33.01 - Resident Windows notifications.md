# Resident Windows notifications

UsefulNotification is a .NET 10 MAUI Blazor application for other programs to call. Its named-pipe broker, scheduler, two HTML surfaces, theme styles, and bounded template/image caches remain resident. The panel opens from the tray. Public contracts and the client are in Core; integration details belong in [the integration guide](../Docs/Integration.md), and frame/template changes in [the appearance guide](../Docs/Appearance.md).

The first pipe implementation combined a UTF-8 byte-order mark, synchronous initialization, and implicit flushing. The working path uses BOM-free UTF-8, a background listener, explicit asynchronous flushes, and a response before shutdown. A request is accepted only after journal persistence; a forced file lock verified rejection and rollback without an uncommitted in-memory notification. Custom HTML was rendered by the real WebView and its declared reply action reached both a callback pipe and stored history.

Native window styles can be reapplied after initial setup. The host removes caption/border/resizing decorations and sanitizes later style changes. It waits for matching rendered cards before showing the notification window, and hides empty surfaces. Runtime checks confirmed no native frame, client area covering the window, queue promotion, snooze, recurrence anchors, expiry after delivery, and no visible empty window after closing. The user confirmed text and the yellow HTML border on screen. Pixel capture returned black while the user played Frostpunk; do not interpret that capture as missing content or repeat screenshot infrastructure. The reference image is 392 by 160 physical pixels; DPI compensation keeps the default notification width at 392 physical pixels.

Use the existing [publish script and build guide](../Docs/Build.md). Restricting NuGet sources to the global package cache caused missing runtime-package errors; normal Visual Studio MSBuild restore downloaded what it needed and published successfully. Do not manually download official runtime packages to work around this. EnableMsixTooling must remain enabled even though WindowsPackageType is None: disabling it omitted the resource index from publishing and the relocated application failed to load MAUI styles. A subsequent relocated Release run passed with resources.pri present. For this WinUI host, setting the process-local WebView2 data-folder environment variable before construction kept browser data under AppCache; the Blazor initialization event property alone did not.

The relocated release was tested from a path containing spaces and a different working directory. The native command apphost sent empty notifications with the real parent process as sender. The GUI launcher preserved a spaced argument. Custom snooze choices, portable paths, both language resources, graceful shutdown, and removal of browser data from AppData were verified. Test projects and journals are outside the repository under C:\C\UsefulNotification; they are not application features or release content. Signing and copying do not require repeating unchanged behavior checks.
