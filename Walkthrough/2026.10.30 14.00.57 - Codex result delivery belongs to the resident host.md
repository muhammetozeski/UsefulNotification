# Codex result delivery belongs to the resident host

Version 3.1.0 adds optional Codex conversation delivery to the existing completion lifecycle. The command sender accepts `--NotifyLLM <ThreadId> Codex` and `-l <ThreadId> Codex`, then exits after ordinary acceptance unless its independent Wait option is selected. The resident host captures the destination with each completed occurrence and launches Codex's native queue command directly through ProcessStartInfo.ArgumentList. No PowerShell helper is shipped or invoked. The public contract is documented in [integration](../Docs/Integration.md#notify-a-codex-conversation).

The earlier investigation confused background execution with starting a new model turn after finalization. A completed tools.exec_command process or yielded functions.exec cell did not restart this conversation in those tests. The existing SendAnonymCodexMessage script instead uses `codex queue --thread --message`; that actual transport was ported into C#. Keep future completion delivery in the broker, independent of sender-process lifetime, card interaction policy, HTML content, or caller polling.

Twenty-five isolated checks used the real command parser and hub with a native executable recording queue arguments. They covered aliases and invalid destinations, full Unicode reply/action/checklist data, body click without sticky lifetime, independent caller waits, expiry and snooze, explicit destination clearing, JSON option order, queue rejection, and restart handling. A real installed Windows host then expired a two-second notification and recorded successful native Codex queue acceptance. Queue acceptance and a model-generated response remain distinct observations.

The journal records an attempt before starting the external queue process. Startup resumes only deliveries that never started; a started failed or uncertain attempt is not automatically replayed. This prevents an application restart from duplicating prompts after an unconfirmed external side effect. Inspect the occurrence's LlmDelivery and original Result when diagnosing delivery; retain these records as user data rather than disposable cache.
